# review20 — preparação privada

`stageReview20` exige que texto e número da solicitação no snapshot coincidam com o registro persistido da revisão; o futuro orquestrador deve ler esse registro antes de chamá-la. Compara o candidato com a base e valida uma resposta estruturada antes de aplicá-la sobre uma cópia JSON em memória. Aceita somente `replace` de valor escalar, com `expectedJson` igual ao valor atual. `basis: base-unchanged` permite criar a primeira alteração quando o valor ainda coincide com a base; um campo já divergente só pode ser refinado com a política explícita `refine-candidate-edit`, evitando sobrescrever edição manual como se ainda fosse base. Uma contradição vira pedido de esclarecimento sem operações. Não chama LLM, não grava candidato/original e não atesta que o L4 completo está válido. O hook do agente ainda não agenda esta etapa; portanto isto é apenas o core parcial de `review20`.
